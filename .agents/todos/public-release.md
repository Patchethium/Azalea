# Azalea — SNS public-preview TODO

Reviewed 8 September 2026. Repository: [Patchethium/Azalea](https://github.com/Patchethium/Azalea). Snapshot: [`master` at 3c5b793](https://github.com/Patchethium/Azalea/commit/3c5b793efb83683fdfbd539bde5f3c90a46e2018).

Recommended scope: a public preview that makes Azalea's character voices, preset workflow, and pitch tuning easy to try and demonstrate. The priorities below are my proposed release cut, based on the current code and roadmap.

This is a source review, not a packaged-app runtime audit. The current commit's [test workflow passed](https://github.com/Patchethium/Azalea/actions/runs/33303569725). The existing 0.2.3 draft is [26 commits behind this snapshot](https://github.com/Patchethium/Azalea/compare/3a05ab5013183fab4ff39c269b706756e7e03775...3c5b793efb83683fdfbd539bde5f3c90a46e2018).

**Fix before release**

- [ ] **R01 · Add an unsaved-change indicator and Save / Discard / Cancel prompts.** Cover New, Open, window close, and Quit. Keep the project marked unsaved after a failed save; record a new project path only after the write succeeds.
- [ ] **R02 · Save projects and settings atomically, with a last-good backup.** Write a temporary sibling file, replace the destination only after a successful write, and retain a recoverable previous version.
- [ ] **R03 · Autosave unnamed drafts and offer Restore Draft on launch.** Recover text, preset assignments, and manual tuning even when the project has never been saved to an .azp file.
- [ ] **R04 · Add undo/redo for block operations, presets, and speech tuning.** Restore deleted/moved/split blocks, preset assignments and values, and accent/phoneme/pitch/duration edits. Treat one slider or pitch drag as one undo step.
- [ ] **R05 · Preserve manual tuning when switching speaker, style, or preset.** Offer Keep Tuning / Regenerate for a voice change, and make resetting tuning an explicit action. Cover every block affected by editing a shared preset.
- [ ] **R06 · Sanitize generated WAV filenames and keep silent exports inside the chosen folder.** Replace path separators and invalid filename characters, reject absolute paths and traversal, handle reserved/empty names, and retain existing collision suffixes.
- [ ] **R07 · Show save, load, synthesis, playback, and export errors with recovery actions.** Name the failed operation and relevant file or voice; provide Retry or Choose Another Location where applicable. Keep failures visible until acknowledged.
- [ ] **R08 · Add a Core setup and startup recovery screen.** Identify missing runtime, OpenJTalk dictionary, and VVM files separately; show incompatible-asset errors; add Retry, Choose Folder, Copy Diagnostics, and Back Up & Reset Broken Configuration.

**Add for the SNS milestone**

- [ ] **R09 · Add a selected-character portrait and speaker thumbnails in the editor.** Show an optional portrait beside the preset editor and compact thumbnails on preset cards or text blocks. Cache downloaded artwork, retain a fallback, and link its attribution/usage information.
- [ ] **R10 · Add Export All: numbered WAV files or one combined WAV.** Export the whole project in block order, preserve configured silences, and show progress, cancellation, failed block names, and the output folder. Reuse the existing collision handling.
- [ ] **R11 · Import .txt files and paste multiline scripts as separate blocks.** Offer line or sentence splitting and apply the selected preset to the new blocks. Keep ordinary paste available inside a single text block.
- [ ] **R12 · Add speaker search and a voice-audition button.** Filter the character picker by name and preview a short Japanese line for the chosen style before applying it to the project.
- [ ] **R13 · Add Save Project As.** Save an edited copy under a new name without replacing the source project; update the active path only after success.

**Prepare the announcement**

- [ ] **R14 · Publish an English/Japanese quickstart with correct Core requirements.** Show the actual folder layout and platform-specific VOICEVOX runtime filenames, a first-voice workflow, and direct platform download links. Replace the contradictory 'older than 0.14.0' guidance. State the .azp schema-1 support boundary and list all three existing UI locales.
- [ ] **R15 · Create a demo .azp, an editor screenshot, and a 30-second video with audio.** Use a short two-speaker Japanese script; show a preset change, pitch/spectrogram tuning, playback, and WAV export. Put the screenshot and playable demo near the top of the README and reuse the clip in the SNS post.
- [x] **R16 · Unify license and application metadata.** Align package.json with the README's GPL-3.0-or-later declaration; replace Cargo's 'A Tauri App' and authors = ['you']; make the About dialog and release notes use consistent project metadata.
- [ ] **R17 · Gate release packaging on tests and rebuild the launch installers from the final tag.** Require the frontend checks/build/tests and real-Core Rust suite before packaging. Produce Windows x64, macOS Apple Silicon, and Linux x64 assets from the selected launch commit; replace the generic draft body with feature notes, platform links, setup instructions, and project-format limitations.

**Keep outside this milestone**

Multi-block selection; notebook command/edit modes; a command palette; guided/reference-audio synthesis; managed Core/model downloads; advanced audio encoders; project-specific dictionaries; and a complete model/memory-management dashboard. Dictionary audition, recent projects, block navigation shortcuts, and pause/resume are useful follow-ups. Whole-project export can ship before multi-block selection.

Use the existing [roadmap](https://github.com/Patchethium/Azalea/blob/3c5b793efb83683fdfbd539bde5f3c90a46e2018/.agents/todos/roadmap.md) for the broader backlog. Keep its release-build verification requirements as the acceptance gate for these deliverables, rather than turning them into vague product TODOs.
